REPRODUCED R3 DEFECT
A Desktop tournament could retain the correct organizer-owned cloudTournamentId while carrying a stale/generated Desktop internalId. r3 rejected that valid provider link when the remote Cloud row localKey differed from the generated local identity, cleared the link, and could CREATE a second private Cloud tournament. Web stayed on the original Cloud row while Desktop synchronized against the duplicate, appearing to the operator as SYNC sending or receiving nothing.

R4 POINT FIX
- Preserve an exact organizer-owned saved cloudTournamentId when it resolves to one Cloud row.
- Repair only blank/legacy-generated Desktop internalId values (cp-tournament:/cp-cloud:) from that exact row when no competing Cloud row owns the generated identity.
- Web-generated tournament:<uuid> identities remain durable and are never treated as disposable.
- Meaningful conflicting identities remain fail-closed.
- Desktop identity candidates now match current Web durable identity candidates; no tournament is selected by name alone.
- Snapshot carries both cloudTournamentId and internalId.
- CREATE first performs organizer-scoped exact stable-identity discovery.
- PUT preflights the current Cloud row metadata and validates identity before X-Expected-Revision guarded write.
- Successful PUT is followed by authoritative snapshot GET and schema-7 fingerprint equality verification.
- Cloud-only pull is fingerprint-verified after durable local apply.
- Existing r3 V140 launcher/LocalEngine and same-origin /cloud-proxy transport are unchanged.
- schema 7, three-way merge, single SYNC authority and protected tournament cores remain unchanged.
