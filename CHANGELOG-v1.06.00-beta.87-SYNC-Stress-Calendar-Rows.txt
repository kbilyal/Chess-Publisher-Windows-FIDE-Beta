Reason for beta.87
A post-beta.86 stress test found two real SYNC gaps in deterministic three-way merge:
1. Desktop edited one Calendar/Schedule row while Web edited a different row.
2. Desktop and Web edited different fields of the same Calendar/Schedule row.

Root cause
The merge engine had stable array identities for players and live pairing boards, but schedule.rows had no stable merge key. Therefore any two-sided schedule.rows change was treated as an atomic array conflict.

Fix
- schedule.rows now use stable logical row identity from row.no (fallback round/id only when present).
- Element-by-element merge is allowed only when base/local/remote contain the same unique row-key sequence in the same order.
- Concurrent add/remove/reorder remains fail-closed and is NOT guessed.
- Same schedule field changed differently remains a true conflict with zero PUT.
- Cloud fingerprint schema stays 7.
- Cloud API/Worker contract is unchanged.
