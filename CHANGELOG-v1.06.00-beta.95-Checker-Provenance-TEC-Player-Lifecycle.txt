Date: 2026-09-10
Status: Windows TEST CANDIDATE

Scope A — Gacrux checker provenance (UI/state orchestration only)
- Adds runtime source, build version and checked timestamp to Gacrux checker UI state.
- Stale checker results from another runtime/build are historical and no longer shown as a current FAIL.
- Legacy Web fallback messages such as "Engine backend not connected ... Desktop only ..." are explicitly ignored as stale when restored through SYNC.
- A fresh current Desktop Gacrux error remains a real FAIL; a fresh success remains PASS.
- Gacrux 1.9.57 runtime/core is unchanged.

Scope B — FIDE/TEC participant lifecycle and Round-1 roster safety
- Adds a strict Chess-Publisher pre-Round-1 Absent gate for Swiss tournaments.
- An active registration marked Absent blocks Resort and Generate Round 1 until the arbiter either marks the participant Present or uses Remove Absent.
- Remove Absent before Round 1 physically removes those registrations and requires Resort Starting List.
- If such a participant arrives after Round 1, adding them again follows the existing Late Entry workflow.
- After tournament start, Absent remains temporary; Withdrawn/Delete remains permanently future-ineligible while historical boards/results/TPNs remain resolvable.
- Post-start withdrawal does not itself trigger a free TPN Resort.

Scope C — Reset Tournament ghost-player repair
- Reset Tournament destroys generated rounds/results and now also physically purges historical registrationDeleted tombstones.
- Active registrations are preserved, including active Absent registrations, which must be resolved before the new Round 1.
- Obsolete tombstone drawing-of-lots state is removed.
- Fixes the supplied saved-tournament case where hidden deleted entries "." and "....." (old TPN 10/11) re-entered fresh Round 1 as 0 BYE after Reset.

Scope D — TRF Starting List
- Round-0 TRF Starting List uses active registrations only and cannot leak historical registrationDeleted tombstones.

FIDE/TEC basis
- FIDE C.04.2 (effective 1 February 2026): Late Entry, TPN handling, withdrawn participants, known absence for a particular round, and played-game-only colour history.
- The stricter pre-Round-1 Absent hard gate is a Chess-Publisher workflow safety policy.
