REAL RUNTIME DEFECT
The previous beta.96 candidate passed mock/schema tests but real Windows Desktop SYNC sent/received nothing. Desktop Cloud fetches still depended on browser CORS between random loopback WebView origin http://127.0.0.1:<port> and the remote Hub Worker. Web deployment gates guarantee the production Web origin, not a stable random Desktop loopback origin contract.

R2 POINT FIX
- Windows Desktop Cloud calls use same-origin /cloud-proxy on ChessPublisher LocalEngine.
- LocalEngine forwards only allowlisted /api/v1/cloud workspace/tournament routes to the fixed Hub Worker host.
- Organizer Bearer token is required and forwarded in memory; it is not logged.
- X-Expected-Revision is validated and forwarded.
- Both unified CloudWorkspaceRedesign and legacy CloudWorkspaceAdapter select the proxy on 127.0.0.1/localhost.
- Production Web keeps the normal direct remote API path and WEB_ORIGIN policy.
- schema 7 and three-way merge/single-authority logic are unchanged.
