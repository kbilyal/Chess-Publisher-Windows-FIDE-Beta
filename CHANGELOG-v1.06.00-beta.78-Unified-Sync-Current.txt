Date: 2026-09-09

Implemented
- My Cloud Tournaments now exposes one user-facing action only: ↕ SYNC.
- Separate Upload Current / Update Current / Pull Current / Upload as New modes are no longer user-facing.
- SYNC determines direction automatically from the current tournament's base/local/remote fingerprints:
  * Desktop-only change -> Push
  * Cloud-only change -> Pull
  * identical -> no-op / refresh sync base
  * non-overlapping Desktop + Cloud edits -> deterministic merge followed by publish in the same SYNC
  * true same-field conflict -> fail closed and open the existing conflict resolver
- The current logical tournament is followed regardless of whether it originated in Web/Cloud or Desktop.
- Desktop-created current tournaments create exactly one Cloud counterpart on first SYNC; subsequent SYNC calls reuse it.
- If an imported/copied file carries a foreign Cloud identity, SYNC first reuses an already existing Cloud row with the current tournament name; otherwise it repairs the foreign identity once and establishes one Cloud counterpart for the current event.
- Download Results remains pairing/result identity-safe, and after the results-only step it also completes the unified SYNC workflow.
- My Online Tournaments no longer displays the PUBLIC LIST eyebrow/label.

- HubAdapter.js is byte-identical; PUBLIC LIST is hidden by the additive CloudWorkspaceRedesign layer.
- CloudWorkspaceAdapter.js is byte-identical.
- Gacrux 1.9.57, Swiss Dutch pairing core, TRF16/TRF26 core, BBP checker, Tie-Break core/checker, Chess-Results protocol/core, player/pairing identity semantics are unchanged.
